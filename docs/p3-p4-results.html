RustTunnel — P3–P4 Result Report

The data plane exists and carries real TCP and real UDP. Seven of eight tasks close on the evidence filed; two remain open for want of a second machine — and the risk gate above them is still open too.

Draft v1 · 2026-08-08 · RustTunnel

Verdict

P3 and P4 were built and run on top of an unproven gate. The WBS puts 2.2 — cross-NAT direct — before any forwarding code, and 2.2 is still not run. This work was done anyway because it was asked for; that is a stated decision, not an oversight. Nothing below depends on hole punching: the data plane is written against an ordinary QUIC connection and is verified over both the direct and the relayed path. If 2.2 eventually reports relayed on both sides, none of this code becomes wrong — the latency and bandwidth argument for v2 does, and the relay numbers below say how much.

Proven

A real HTTP client and a real sshd reached through the tunnel. 100 MiB byte-exact with matching digests. Two concurrent transfers that stayed independent. A real resolver answering real queries. Sessions reaped and their sockets returned, confirmed by lsof. The size cap failing loudly at a measured boundary. Both port allowlists refusing live services.

Not proven

That the far end is a different machine — hostname is the same string on both sides of a one-Mac rig. That WireGuard completes a handshake through it: two utuns on one host fight over routes, so the substitute covers the sustained-flow half only.

Found by running it

A fake green that passed every assertion while rtun carried nothing, a relay far too slow for the planned transfer sizes, and a port the plan picked that macOS already owns. All three are in findings.

Hình 1 — Both directions of every stream are one tokio::io::copy_bidirectional over join(recv, send), which is also what maps a stream FIN onto a TCP FIN. No custom pump loop was written.
FileAdded
src/proto.rsNew. Four functions: the two-byte stream header and the six-byte datagram prefix, plus a runt check that refuses anything shorter than the header.
src/connect.rsLocal TCP listeners and UDP sockets, all bound before the dial; one QUIC stream per accepted TCP connection; the session table keyed by (source address, target port); the reply pump and the reaper.
src/serve.rsThe stream accept loop with the --tcp check, and the datagram pump with the --udp check; one dedicated socket per session id with its own reply task; the reaper.
src/tunnel.rsThe plan's five in-process cases. A bin crate cannot have tests/tunnel.rs import it, so it is a #[cfg(test)] module of the same name rather than an integration test.
src/main.rsUDP_IDLE (60 s) and UDP_REAP_INTERVAL (5 s); the port lists now reach serve as an Offered allowlist instead of being logged and discarded.
One dependency added: bytes. Connection::send_datagram takes a bytes::Bytes and iroh does not re-export the type, so it has to be named. It was already in the tree transitively, so nothing new ships.

The relay is two to three orders of magnitude slower than the direct path, and it is not consistent. 121 MB/s against 920 KB/s is 130×; against the 134 KB/s measured an hour earlier on the same rig it is 900×. That spread is itself the finding — the default relay is free shared infrastructure and its throughput is not something to plan around. The e2e plan's advice to cap the relayed bulk file at 10 MB was right and did not go far enough: the concurrent pair needs the same treatment. The first 3.4 attempt left them at 50 MiB each; after 300 seconds they had moved 35 MiB each and curl's own timeout killed them. This is the concrete cost behind 2.2's gate condition — "accept relayed operation" means accepting this number.

Findings

Three of these are about the harness rather than the product, which is the point of running checks against real binaries: the harness is where the lying happens.

FindingDisposition
1 A fake green that passed every assertion while rtun carried nothing. Reading a run's output through head closed the pipe, SIGPIPE killed the script before its teardown, and a leftover connect from the previous run kept port 2222. The next run — --relay-only — failed to bind, exited, and the old direct tunnel served every byte. Token matched, digests matched, 121 MB/s "over the relay". The harness now refuses to start if the mapped port is already held, requires an established line in this run's own connect.log, requires stream opened on the serving side before believing a transfer, and tears down through a trap. This is the sixth entry in the e2e plan's fake-green traps, met in the wild.
2 rtun made that failure visible rather than silent, because listeners are bound before the dial: the stale port produced Error: binding tcp 127.0.0.1:2222 · Address already in use and a non-zero exit, instead of a connected tunnel with nothing listening on it. Working as designed. Worth keeping when 5.1 adds a retry loop — a bind failure is not something to retry.
3 The plan's DNS port is unusable on macOS. dnsmasq on 5353 fails with Address already in use: mDNSResponder owns UDP 5353 systemwide, and lsof does not show it without root, so the cause is not obvious from the error. 4.1 runs on 15353 → 15354 instead. The e2e plan's 4.1 procedure should say so.
4 Two of five streams logged Connection reset by peer at close on the relayed path — once, and not reproducibly. It appeared in the slow relayed run (134 KB/s) and not in the filed one (920 KB/s), which logged zero failures on either side. All digests matched in both, so no payload was lost either way; the reset lands after the body is delivered, when the local service closes with unread bytes still in its receive buffer. Left as a WARN deliberately, and left unfixed. A close-time reset cannot be told from a mid-transfer reset by its error alone, so demoting it would hide the case that does lose data. Worth revisiting only if it starts appearing on the direct path, where it never has.
5 The --udp port list is the same open door as --tcp, and the WBS has no task for it. Without the check, one allowlisted peer reaches every UDP port on the loopback interface. Implemented and checked the same way — two live echoes, one offered. Filed as evidence/local/3.2-udp/. The WBS should fold it into 3.2's wording.
6 connect still exits 0 when the allowlist refuses it — carried over from P1.3 and untouched here. Left alone on purpose: it is 5.1's task, and it is already written down there. Nothing in P3 or P4 depends on the exit status.

Ceilings, as observed

CeilingWhat it measured
UDP payload capped at the QUIC datagram size1408 bytes on this path. 1400 crosses, 2000 is refused with the size and the cap both in the log line. The cap is whatever QUIC can carry at that moment, so it is not a constant to hard-code.
Idle sessions reaped on a timer60 s idle, swept every 5 s, so a session outlives its last datagram by at most 65 s. One sweep for the whole table — per-session timers only matter once the table is large.
One peer connection at a timeUntouched. The serving side accepts many connections and gives each its own session table, but no check exercises two peers at once.
One global lock per session tableNever held across an await; the guard is bound out of the match so a slow socket cannot block the table. Adequate at 1084 datagrams/minute — unmeasured above that.

The in-process check

All five cases from the plan's one check now exist, plus two unit tests. Seven pass in 2.1 s with no network, no fixtures and no mocks.

CaseWhat would break it
tcp_round_trip_is_byte_exactFraming, stream routing, or a lost FIN — the test half-closes and reads to EOF, so a reply can only arrive if the close crossed and came back.
concurrent_tcp_connections_do_not_interleaveStreams crossing. Distinct fill bytes and distinct lengths, so neither a swap nor a partial cross reads as a pass.
udp_replies_reach_the_correct_local_sourceA session table keyed wrongly: two local sockets send, and each must get its own payload back.
allowlist_admits_only_listed_peersThe peer allowlist. Moved here from serve.rs unchanged.
unoffered_tcp_port_is_refusedThe port allowlist — and it was rewritten because the first version could not fail. It pointed at a dead port, so the stream failed whether or not the check existed. It now runs two live echo services and offers one.
datagram_round_trips_and_rejects_runtsThe six-byte prefix, including the zero-length payload case and everything shorter than a header.
The port-allowlist case was mutation-checked. Replacing if !tcp.contains(&port) with if false makes it fail; restoring it makes it pass. A check that has never been seen to fail is a check nobody has tested.
